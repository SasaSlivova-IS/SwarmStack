# Working on SwarmStack

This is a reusable toolkit, not an application or authority to manage another project. Follow the current user request and higher-priority host instructions.

Inspect status before editing; preserve WIP. Do not change global skills, other repositories, harness configuration or real accounts. Read [design](docs/design.md) for structural changes, [models](guides/models.md) for routing, and [setup](SETUP.md) for adoption. Keep universal guidance free of project-specific paths, temporary blockers, credentials and subscription assumptions. Never publish private-project names, purposes or identifiers; generalise examples and audit the full history, not only HEAD.

Keep scripts standard-library only and preview-first. Bootstrap must not execute project commands or overwrite existing files. Test meaningful successful and refused paths in temporary projects. Run `python3 scripts/check.py` and `python3 -m unittest discover -s tests -v`; these do not prove every host or adopted project works.

Before initial delivery or material workflow changes, use [code-review](skills/code-review/SKILL.md) for independent Standards and Spec review, plus Security when installation/authority/data boundaries change. Reviewers are read-only; the implementer owns fixes. Review grants no publication, spending or deployment authority.

Preserve upstream notices and record adaptations. Keep evidence compact; no raw session dumps, caches or recursively copied inventories. Use concise concrete English.
