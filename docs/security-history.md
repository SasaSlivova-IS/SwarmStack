# Public sharing

Publish reusable guidance, original scripts, synthetic examples and appropriately licensed skill procedures only. Exclude private-project names, purposes, identifiers, code, credentials and raw session history, including comments explaining what was excluded.

Audit every revision reachable from every branch/tag intended for publication, not only current files. Use GitHub noreply identities where appropriate. Keep private backup bundles and revision mappings outside tracked content.

Imported skills need origin/license review; updates should be pinned and diff-reviewed. Real project configurations and evaluation evidence belong in their own authorised repositories.

If confidential material is published, restrict access, remove it from current files and reachable history, and assess hosting caches, forks and existing copies separately. A history rewrite cannot recall other people's copies or guarantee cache removal. Revoke exposed credentials first; deleting their text does not revoke access.
